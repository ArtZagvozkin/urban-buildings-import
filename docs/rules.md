# Правила данных, результатов и API

## Исходники и подготовка

`config/territories.json` задаёт территории: Реутов 5231, Жуковский 5202,
Лотошино 5215, Одинцовский 5223. Тип 4 — жилое, 5 — нежилое. Жилой физический
объект имеет дополнительную запись buildings. OSM ID хранится отдельно от
серверных ID; новые ID всегда выдаёт API.

Исходные GeoJSON неизменяемы. Для завершённых результатов используется
историческая муниципальная граница из `reference/boundaries/`, совпадающая с
хешем исходной подготовки. `reproduce` не обращается к сети. Год проверки
зафиксирован в результате: 2026. Для нового импорта `prepare --live-boundary`
получает новую границу API; прежний подтверждённый результат не изменяется.

Проверяются пустые и неполигональные геометрии, валидность, самопересечения,
повторы OSM ID и нормализованной геометрии. Площадь вычисляется геодезически
на WGS84, не в квадратных градусах. `make_valid` допустим при сохранении
Polygon/MultiPolygon и изменении площади не более 0,1%; исправления отражаются
в отчёте. Геометрия должна целиком покрываться муниципальной границей.

Назначение файла должно совпадать с `is_living`. Явно жилые теги в нежилом
файле, нежилые теги и коммерческие, общественные или инженерные признаки в
жилом исключаются. Противоречивый объект не переклассифицируется без доказательства.
Исключённые объекты заново выводятся в `prepared/disputed.geojson` при prepare.

Адрес передаётся при наличии номера дома и улицы либо места. Этажность —
положительное целое до 150; год — целое от 1700 до года проверки. Отсутствующие
характеристики не выдумываются. Известные OSM-теги сохраняются в properties.

Восемь файлов Одинцова образуют полный набор территории, подтверждённый для
завершённого запуска. Части перекрываются и не задают географические сектора.
Новая территория может иметь несколько файлов одного типа; алгоритм не копируется.
